### Context Engineering 🔥

- **定义**：Context Engineering（上下文工程）是一门设计、组织和优化输入给语言模型的完整信息环境（包括系统指令、检索文档、工具定义、记忆、模式等）的学科，而非仅仅优化用户提示词。Andrej Karpathy 将其定义为："填充上下文窗口时，为下一步提供恰好正确信息的精致艺术和科学。"
- **起源追溯**：该术语最早由 Andrej Karpathy 在 2025 年末至 2026 年初的推文和演讲中推广。2026 年 2 月，Damon McMillan 在 Springer 发表的同行评审研究 "Learning with large language models: beyond prompt engineering" 通过 9,649 次实验验证了这一范式的有效性。随后 Martin Fowler、Simon Willison 等权威博主在 2026 年 Q1-Q2 持续传播该概念。
- **提出背景**：Prompt Engineering 在实践中暴露出根本性局限：对措辞高度敏感、跨模型不可迁移、模型更新后失效、企业规模下难以维护。McMillan 的研究发现，提示词格式（YAML/Markdown/JSON/TOON）对结果无统计学显著影响（p=0.484），而模型选择带来 21 个百分点的准确率差距。这促使社区将焦点从"如何提问"转向"提供什么上下文"。
- **使用场景**：企业 RAG 系统架构设计、Agent 工具定义与记忆管理、长上下文窗口优化、多轮对话状态维护、代码库级 AI 辅助开发。
- **交叉验证**：Springer 同行评审论文、Martin Fowler 的 "Structured-Prompt-Driven Development"（2026 年 4 月 28 日）、Simon Willison 的博客系列、多个企业技术博客（Serenities AI、Polyglotsoft、VibeHackers）均独立讨论此概念。
- **争议与质疑**：部分从业者认为这仅是 Prompt Engineering 的 rebranding。但 2026 年的方法论体系化程度（四层级技能框架：Prompt Craft → Context Engineering → Intent Engineering → Specification Engineering）表明这是真正的范式演进。
- **相关链接**：
  - [Learning with large language models: beyond prompt engineering](https://link.springer.com/article/10.1007/s10639-026-13924-2)
  - [Context Engineering: Replacing Prompt Engineering 2026](https://serenitiesai.com/articles/context-engineering-replacing-prompt-engineering-2026)

### Agent Skills / Skills Files 🔥

- **定义**：Agent Skills（或 Skills Files）是将 AI 编码代理的能力、行为规范、工具访问权限和领域知识封装为可版本控制的文本文件（通常置于 `.claude/skills/` 或类似目录），使代理能够按需加载特定技能以完成特定任务。
- **起源追溯**：该模式由 Claude Code 的 hooks/skills 系统演化而来。2026 年 4 月，Matt Pocock 发布 `mattpocock/skills` 仓库，将个人 `.claude` 目录公开，迅速获得社区关注。同期 Andrej Karpathy 发布关于 LLM 编码陷阱的观察，被社区转化为 `forrestchang/andrej-karpathy-skills`（单文件 CLAUDE.md），两周内获得 11 万+ stars。Addy Osmani 随后推出 `addyosmani/agent-skills`，将概念推广到生产级工程实践。
- **提出背景**：随着 Claude Code、Codex、Cursor 等编码代理的普及，开发者发现重复为相似任务编写指令效率低下。将最佳实践封装为可复用的 Skills 文件，实现了"一次编写，随处使用"，同时便于团队协作和版本控制。
- **使用场景**：编码规范标准化、框架特定开发（React/Vue/Rust 等）、代码审查自动化、安全合规检查、新团队成员快速上手。
- **交叉验证**：GitHub Trending 周榜和月榜同时出现 4+ 个 Skills 相关项目（mattpocock/skills、addyosmani/agent-skills、browserbase/skills、ComposioHQ/awesome-codex-skills），累计月增星超 20 万。OpenAI 的 Symphony 和 Anthropic 的 financial-services 项目也采用类似模式。
- **争议与质疑**：部分开发者担忧 Skills 碎片化会导致"配置地狱"，且不同代理（Claude Code vs Codex vs Cursor）的技能格式不统一，互操作性有限。
- **相关链接**：
  - [mattpocock/skills](https://github.com/mattpocock/skills)
  - [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)
  - [forrestchang/andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills)

### A2A (Agent-to-Agent) Protocol 🌱

- **定义**：A2A（Agent-to-Agent Protocol）是一种开放的、 vendor-neutral 的协议，用于实现不同框架、不同厂商开发的 AI Agent 之间的对等通信和任务协作。它允许 Agent 自动发现彼此的能力（通过 "Agent Cards"），协商任务分配，并交换结构化结果。
- **起源追溯**：A2A 由 Google 于 2025 年提出并开源，最初作为 Google ADK 的一部分发布。IBM 同期推出了竞争协议 ACP（Agent Communication Protocol）。2025 年末至 2026 年初，Linux 基金会介入协调，ACP 正式并入 A2A，形成统一标准。
- **提出背景**：随着多 Agent 系统的普及，不同框架（LangGraph、CrewAI、Claude Agent SDK、OpenAI Agents SDK 等）之间的互操作性成为关键瓶颈。每个框架使用不同的消息格式和编排方式，导致企业难以构建跨框架的 Agent 生态。
- **使用场景**：跨部门 Agent 协作（如财务 Agent 与销售 Agent 对接）、多厂商 Agent 集成、企业级 Agent 市场中第三方 Agent 的发现与调用、供应链自动化中的多方 Agent 协调。
- **交叉验证**：Google ADK 官方文档、Linux 基金会公告、CrewAI 的 A2A 原生支持（45,900+ stars 的框架采用）、多个 2026 年 4-5 月的技术对比文章（MorphLLM、HolySheep、Flowtivity）均确认 A2A 的统一地位。
- **争议与质疑**：MCP（Model Context Protocol）和 A2A 的边界仍不够清晰——前者侧重应用到模型的工具访问，后者侧重 Agent 间通信。部分开发者担忧 Google 在标准制定中的主导权过大。
- **相关链接**：
  - [Google A2A Protocol](https://developers.google.com/agent-development-kit/a2a)
  - [Linux Foundation Announcement](https://www.linuxfoundation.org)
  - [A2A vs MCP vs ACP 对比](https://www.morphllm.com/ai-agent-framework)

### Agentic Coding / Coding Agent Harness 🔥

- **定义**：Agentic Coding 指 AI 系统不仅能辅助编写代码片段，还能自主规划、执行、调试和交付完整的软件项目。"Coding Agent Harness" 是一类新兴框架，为这种自主编码 Agent 提供运行环境、工具访问、状态管理和安全沙箱。
- **起源追溯**：该概念的早期形态可追溯至 2024 年的 Devin（Cognition Labs），但 2026 年的主流化由多个因素共同推动：Claude Code（Anthropic）和 Codex（OpenAI）的 CLI 工具普及、Andrej Karpathy 2026 年 2 月提出的 "Agentic Engineering" 概念、以及本期 GitHub Trending 上涌现的多个 Harness 项目（jcode、Symphony、DeepSeek-TUI）。
- **提出背景**：编码代理的能力在 2026 年发生质变——从"补全当前行"到"实现整个功能"再到"交付完整项目"。这要求新的基础设施：项目级别的上下文管理、多文件协调、版本控制集成、CI/CD 对接、以及人类审查节点。
- **使用场景**：全栈应用自动生成、遗留代码现代化、跨语言代码迁移、自动化代码审查与重构、24/7 运行的开发流水线。
- **交叉验证**：OpenAI 官方发布 Symphony（23,214 stars）、DeepSeek-TUI（24,306 stars，单周增 22,034）、jcode（Coding Agent Harness）均在本期 Trending 上榜。Phil Schmid 在 2026 年 5 月的 "10 Lessons for Agentic Coding" 博客中系统总结了最佳实践。
- **争议与质疑**：质量与维护成本问题突出——James Shore 等从业者指出，许多 AI 生成代码优先考虑速度而非长期可维护性。PS3 模拟器开发者公开请求停止提交 AI 生成的 PR。Cloudflare 称 AI 使其 1,100 个岗位变得冗余。

  - [1jehuang/jcode](https://github.com/1jehuang/jcode)
  - [10 Lessons for Agentic Coding](https://www.philschmid.de/2026/05/04/10-lessons-for-agentic-coding.html)

### Vibe Physics 🧪

- **定义**：Vibe Physics 指使用大型语言模型（特别是 GPT 系列）在理论物理和量子引力等高度抽象的数学领域进行探索性研究，让模型自主推导新的数学关系、验证猜想或发现新的证明路径。
- **起源追溯**：该术语由 Latent Space 播客在 2026 年 5 月 5 日的 episode "Doing Vibe Physics — Alex Lupsasca, OpenAI" 中首次命名。Alex Lupsasca 描述了使用 GPT-5.x 在理论物理和量子引力中获得新结果的经历。
- **提出背景**：随着模型推理能力的提升（特别是 o1/GPT-5 系列的长思维链），研究者开始将 LLM 不仅作为写作辅助工具，而是作为真正的"研究合作伙伴"，在自身专业领域进行创造性探索。
- **使用场景**：数学猜想验证、物理理论探索、跨学科概念映射、复杂证明的辅助构建、新研究方向的头脑风暴。
- **交叉验证**：目前主要来源为 Latent Space 播客单一来源，OpenAI 官方未独立发布相关研究。【未经核实】该概念是否构成可复现的方法论体系仍待验证。
- **争议与质疑**：科学界对 AI 生成数学结果的可靠性持高度怀疑态度。缺乏同行评审的严格验证，且 LLM 的幻觉问题在抽象数学领域可能更难检测。
- **相关链接**：
  - [Doing Vibe Physics — Latent Space](https://www.latent.space/p/lupsasca)
