### Model Hardware Standard (MHS) 🔥

- **定义**：由 Anthropic 主导、与 HHMI Janelia Research Campus 联合开发的开放规范，目标是为 AI Agent 操作物理设备（机器人、IoT、机械臂、激光器等实验室仪器）定义一套类似 MCP 的统一接口、设备发现机制与安全护栏。
- **起源追溯**：2026-08-27 Anthropic 开放 MHS 研究预览；具体提出者为 Anthropic（Beneficial Deployments）的 Alek Kemeny 与 Janelia 博士后 Arco Bast。合作伙伴包括 AWS、Hugging Face、Raspberry Pi、Genentech、QuEra、CMU、UW、Danaher、Doosan Robotics、MBF Bioscience、QIAGEN、Tecan、Universal Robots、Tetsuwan Scientific、Automata。
- **提出背景**：MCP 在软件侧已统一了 Agent 工具连接的事实标准；MHS 是其在物理侧的对标。引人注目的早期结果是 QuEra Computing 激光重锁成功率从 58% 提升至 99.3%（700 次试验）。
- **使用场景**：实验室仪器、工业机器人、消费级机械臂、智能家居设备的 Agent 化操作；解决厂商锁定与设备发现难题，将集成周期从数周缩短到数小时。
- **交叉验证**：[Techstrong.ai](https://techstrong.ai/articles/anthropic-debuts-hardware-standard-for-physical-ai)、[AlphaSignal](https://alphasignal.ai/news/anthropic-s-model-hardware-standard-lets-claude-control-lab-robots-overnight)、[Time.news](https://time.news/anthropic-introduces-ai-hardware-standard)、[The Decoder](https://the-decoder.com/anthropic-wants-to-do-for-physical-hardware-what-its-model-context-protocol-did-for-software/)、[QbitAI](https://www.qbitai.com/2026/08/480487.html) 等 5+ 独立来源覆盖。
- **争议与质疑**：[RobotAIGeek](https://www.robotaigeek.com/ai-robotics/robotics-platforms-ecosystems/the-robot-safety-standard-with-exactly-one-author) 指出 MHS 由 Anthropic 单独治理，对照 ISO 10218 历时 15 年的多利益相关方流程，是治理风险；[Pick Right](https://pick-right.com/news/anthropic-model-hardware-standard-mcp-playbook-physical-layer-2026-08-29) 指出 SiLA 2 与 OPC UA LADS 已存在，MHS 形成协议碎片；同时欧盟机械法规 2023/1230（2027-01-20 生效）可能将 MHS 安全文件归类为受监管安全组件。

### Agent Skill 🔥

- **定义**：以单一能力为粒度的轻量化打包单元（以含 `SKILL.md`（YAML frontmatter + Markdown 正文）的文件夹为核心，可附 `scripts/`、`references/`、`assets/`），让 AI Coding Agent（Claude Code、Codex、Cursor 等）通过加载 Skill 获得特定能力。
- **起源追溯**：[Anthropic 工程博客《Equipping agents for the real world with Agent Skills》](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) 于 2025-10-16 正式发布 Agent Skills；采用"渐进式披露"（Progressive Disclosure）三级加载：启动时仅加载 `name`+`description`，相关时加载完整正文，按需加载捆绑资源。[anthropics/skills](https://github.com/anthropics/skills) 仓库已获 17.27 万 star、20.5k fork。
- **标准化进程**：2025-12-18 Anthropic 将其作为开放标准发布至 [agentskills.io](https://agentskills.io/home)；规范代码库位于 [github.com/agentskills/agentskills](https://github.com/agentskills/agentskills)（Apache-2.0/CC-BY-4.0），现归 Linux Foundation 旗下 Agentic AI Foundation（AAIF）管辖；已被 Claude Code、OpenAI Codex、GitHub Copilot、VS Code、Cursor、Gemini CLI、Goose、Roo Code、Kiro 等 40+ 工具支持。
- **提出背景**：随着模型能力通用化，"如何为特定任务打包专家知识"成为新工程问题。Skill 与 MCP 互补而非竞争：MCP 标准化"如何连接工具/数据"，Agent Skills 标准化"拿到工具后该怎么做"。
- **使用场景**：垂直场景（科研、求职、逆向、绘制架构图、法律等）的即插即用；[K-Dense-AI/scientific-agent-skills](https://github.com/K-Dense-AI/scientific-agent-skills) 是科研向代表；[tt-a1i/archify](https://github.com/tt-a1i/archify) 是架构图向代表；[virgiliojr94/book-to-skill](https://github.com/virgiliojr94/book-to-skill) 把 PDF 转为 Skill 是元能力向代表。
- **交叉验证**：[Shiplight](https://www.shiplight.ai/blog/agent-skills)、[Mushroom CV](https://blog.mushroom.cv/blog/agent-skills-open-standard-progressive-disclosure-anthropic)、[LM-Kit](https://lm-kit.com/blog/agent-skills-explained) 多家独立分析师博客覆盖一致；社区仓库均遵循同一格式规范。
- **争议与质疑**：尚无系统性反对意见；标准化成熟度低于 MCP，但生态扩张速度更快。

### Harness Engineering 🔥

- **定义**：把模型视为内核、把围绕模型的一切（提示词、工具、状态机、记忆、调度、协议、恢复、权限、监控）统称为 Harness 的工程学科。LangChain Vivek Trivedy 名言："If you're not the model, you're the harness." Agent 的实际效能取决于 Harness 而非模型本身。
- **起源追溯**：[Mitchell Hashimoto（HashiCorp 联合创始人，Terraform/Vagrant/Vault 作者）2026-02-05 发表博客《My AI Adoption Journey》](https://mitchellh.com/writing/my-ai-adoption-journey)，在 Step 5「Engineer the Harness」中正式命名 "Harness Engineering" 概念。[OpenAI 2026-02-11 官方博客《Harness engineering: leveraging Codex in an agent-first world》](https://openai.com/index/harness-engineering/) 迅速跟进，披露 3 名工程师 5 个月产出 100 万行代码、1500 PR、零手写代码的实践案例。术语 2-3 周内被 Anthropic、Martin Fowler、Thoughtworks Birgitta Böckeler 等主流采纳。
- **使用场景**：Anthropic Claude Code SDK 官方定义为 "the agent harness that drives Claude Code"，采用 Planner→Generator→Evaluator 三智能体架构，任务接受准确率 94%；OpenAI Codex 8 月升级 "Ralph Wiggum Loop"（PR 自审闭环）与 AGENTS.md + docs/ 仓库嵌入式知识结构。DeepSeek 同名异用——其开源 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)（"Everything is a Plugin" 插件化 AI Agent 运行时）属于产品命名而非工程学科，需明确区分。
- **交叉验证**：[OpenAI Harness engineering 博客](https://openai.com/index/harness-engineering/)、[InfoQ 报道](https://www.infoq.com/news/2026/02/openai-harness-engineering-codex/)、[Software Improvement Group 分析](https://www.softwareimprovementgroup.com/blog/what-is-harness-engineering)、[Hypercore 简史](https://www.hypercore.ai/blog-article/how-ai-models-became-agents-a-short-history-of-harness-engineering)、[Milvus Blog](https://milvus.io/blog/harness-engineering-ai-agents.md) 多家独立来源覆盖一致。
- **争议与质疑**：[2026 年初 Evolution Engineering](http://rotifer.dev/blog/evolution-engineering) 提出更激进的四阶段演化（Prompt → Context → Harness → Evolution），与 Harness Engineering 部分存在语义重叠；术语在不同厂商间用法不完全一致（DeepSeek 偏产品命名，OpenAI/Anthropic 偏工程学科）。

### WikiSkill 🔥

- **定义**：Google Research 提出的 Agent 自演化机制；通过 Raw Layer（不可变执行轨迹）→ Wiki Layer（蒸馏失败/成功/策略模式）→ Skill Layer（可执行指令）三层架构，把 Agent 的真实经验编译成可持久化、可跨任务/跨模型复用的 wiki 知识。
- **起源追溯**：[论文《WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution》](https://arxiv.org/abs/2608.27454)，arXiv ID 2608.27454，分类 cs.AI/cs.CL，提交 2026-08-27；作者 Liyan Tang、Cyrus Rashtchian、Chun-Sung Ferng、Andrew Tomkins、Da-Cheng Juan、Tu Vu（最后一位另隶属 Virginia Tech）。
- **提出背景**：现有 Agent 无长期记忆，反复犯同样错误；WikiSkill 用 wiki 形式结构化条目而非纯向量检索，强调"演化"与"技能复用"。关键结论：9B 模型 + WikiSkill 得分 47.4%，优于无 WikiSkill 的 27B 模型（39.4%）；且技能可在不同模型之间迁移，跨家族复用甚至优于自演化。
- **使用场景**：需要长期可靠工作的 Agent（客服、运维、个人助理、编码 Agent）；解决"反复试错"和"上下文漂移"问题。
- **交叉验证**：[TokenFeed 分析](https://tokenfeed.ai/ai-agents-now-keep-a-wiki-of-their-own-failures)、[Emergent Mind 含局限性分析](https://www.emergentmind.com/papers/2608.27454)、[智源社区论文页](https://hub.baai.ac.cn/paper/447a6ab8-47ba-4f79-a610-1f102717dbf1)、[arXiv TLDR](https://arxivtldr.org/abs/2608.27454)、[The Decoder](https://the-decoder.com/google-gives-ai-agents-their-own-wiki-so-they-can-learn-from-mistakes-and-successes/) 多家独立媒体覆盖一致。
- **争议与质疑**：与 SABER（Google DeepMind 机器人技能评估基准）主题相关但非同一项目，需在引用时区分；与 RAG 的边界（wiki 式条目 vs 纯向量检索）需进一步厘清。
- **相关链接**：

  - [The Decoder — Google gives AI agents their own wiki](https://the-decoder.com/google-gives-ai-agents-their-own-wiki-so-they-can-learn-from-mistakes-and-successes/)

### Agent OS 🌱

- **定义**：以 AI Agent 为一等公民设计的操作系统级抽象：跨进程消息总线、人机共生资源调度、Agent 应用的 markdown-as-app 表示、Agent 群体的实时治理控制室。
- **起源追溯**：2026-08 窗口 arXiv 同时间出现 3 篇已验证论文形成集群——[CrabOS: An Operating System for Human-AI Co-inhabitation（arXiv 2608.28165）](https://arxiv.org/abs/2608.28165)（Qi Yang, Yun Ma，提交 2026-08-28，cs.AI/cs.HC/cs.OS）、[GOD: Govern, Observe, and Direct — A Real-Time Control Room for Agent Societies（arXiv 2608.27992）](https://arxiv.org/abs/2608.27992)（Govern/Observe/Direct 三支柱框架）、[Logos: An Agent Harness on a Cross-Process Bus（arXiv 2608.28553）](https://arxiv.org/abs/2608.28553)（Hanzhang Jia et al. (Sussex)，AAMAS 2027 录用，ROS 风格跨进程总线、append-only transcript、对等进程故障隔离）。Karpathy 2023 年 3 月基于 AutoGPT 提出的 "Software-Agent Operating System" 概念是该方向的更早原形；2026-03 Liu et al. (Univ. of Kansas) 论文 [AgentOS](http://scirate.com/arxiv/2603.08938) 是另一独立并行路线，主张 NL-portal/skill-module/intent-orchestrator 栈。
- **使用场景**：多 Agent 协同、Agent 群体治理、人机共生计算集群、工业 Agent 群控。
- **交叉验证**：[Serious Insights 行业预测](https://www.seriousinsights.net/agentic-operating-system)、[FuturePicker 中文分析](https://futurepicker.com/agent-os-next-operating-system-no-desktop-2026)、[yarnnn blog](https://www.yarnnn.com/blog/the-agent-os-is-real)、[Tencent ContextPilot InfoQ talk](https://www.infoq.com/presentations/tencent-context-engineering-agent/) 等独立来源呼应。
- **争议与质疑**：传统容器/VM 并非为 Agent 工作负载设计——Celesto、Agent Patterns、Helix.ml 等多家分析师收敛于 microVM + 意图范围特权的"缺失层"观点，但 Agent OS 工业化产品尚未成形。

### Test-Time Compute Allocation 🌱

- **定义**：在模型权重固定的前提下，通过运行时自适应分配算力来提升任务表现的工程范式；具体技术包括自适应证据分配、早期退出、Hessian 引导的量化、长链路信用分配。
- **起源追溯**：本窗口 arXiv 出现 4 篇代表论文——[AERA: Adaptive Evidence Residual Allocation（arxiv 2608.27964）](https://arxiv.org/abs/2608.27964)、[SABER: Stability-Aware Early Exit（arxiv 2608.27963，EMNLP 2026）](https://arxiv.org/abs/2608.27963)、[H-Scale: Hessian-Guided Scale Refinement for NVFP4 Sub-Byte LLM Inference（arxiv 2608.28113）](https://arxiv.org/abs/2608.28113)、[Sliding-window beats linear attention（arxiv 2608.28444）](https://arxiv.org/abs/2608.28444)。这些是同一研究趋势的不同切面：测试时计算正在取代模型规模成为新的扩展维度。
- **提出背景**：当模型预训练成本快速攀升，扩展轴从"训练更大模型"转向"推理时更聪明地使用算力"，与 OpenAI 的 o1 路线一脉相承。
- **使用场景**：长链路推理（数学/代码/规划）、低延迟服务、低显存推理。
- **交叉验证**：上述 4 篇 arXiv 论文同期发表；EMNLP 2026 / EMNLP Findings 多篇相关工作（[VICT verifier-instrumented credit tracing](https://arxiv.org/abs/2608.28128)、[AERA](https://arxiv.org/abs/2608.27964)）已被会议接收。
- **争议与质疑**：运行时分配的计算开销是否抵消其收益在不同任务上差异显著；尚未形成统一基准。
