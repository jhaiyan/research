### Context Engineering 🔥

- **定义**：一种针对 AI Agent 和 LLM 应用的上游系统工程实践，涵盖上下文的 **Write（写入）、Select（选择）、Compress（压缩）、Isolate（隔离）** 四大核心操作。生产环境中，Prompt 仅占 Agent 上下文预算的 5%，其余 95% 来自检索、记忆、工具调用和架构设计。

- **起源追溯**：
  - **2001 年**：Anind K. Dey（Georgia Tech）奠定上下文计算的学术基础
  - **2025 年 6 月**：Tobi Lütke（Shopify CEO）称其为"最高杠杆技能"
  - **2025 年 6 月**：Andrej Karpathy 正式命名并推广
  - **2025 年 9 月**：Anthropic 官方文档采用该术语
  - **2026 年初**：LangChain、Sequoia、Princeton 跟进系统化
  - **2026 年 4 月 6 日**：ByteByteGo 文章引发主流传播

- **提出背景**：解决 LLM 应用中上下文管理碎片化问题。传统做法将 Prompt Engineering 局限于措辞优化，而 Context Engineering 将其扩展为涵盖 RAG、记忆系统、工具调用和上下文隔离的完整工程体系。

- **使用场景**：
  - AI Agent 的长期记忆管理
  - 多轮对话的上下文压缩与检索
  - RAG 系统的上下文选择策略
  - Agent 间的上下文隔离

- **交叉验证**：
  - ByteByteGo（2026-04-06）、Towards AI、Anthropic 官方文档、LangChain/Sequoia、Princeton 研究、Martin Fowler、Simon Willison 等多个独立来源确认

- **争议与质疑**：
  - 部分观点认为"只是重新包装已有实践"，但 Context Engineering 的系统化框架得到广泛认可

- **相关链接**：

  - [Anthropic: Context Engineering](https://docs.anthropic.com)

### Harness Engineering 🔥

- **定义**：围绕 AI Coding Agent 设计和构建**约束机制、反馈回路、工作流控制和持续改进循环**的系统工程实践。核心公式：**Agent = Model + Harness**。两个核心组件：**Guides（引导）** 提供前馈控制，**Sensors（传感器）** 提供反馈控制。

- **起源追溯**：
  - **2026 年 2 月 5 日**：Mitchell Hashimoto 首次提出概念
  - **2026 年 2 月 17 日**：Birgitta Böckeler（Martin Fowler）发布早期备忘录
  - **2026 年 4 月 2 日**：Böckeler 在 Martin Fowler 发布完整系统性框架
  - **2026 年早期**：OpenAI 工程博客发布 Harness Engineering 案例研究

- **提出背景**：解决 AI Coding Agent 在长时间运行中出现重复错误的根本问题。通过工程化手段（Guides + Sensors）实现"一次发现错误，永远避免同类错误"的系统性改进。

- **使用场景**：
  - AI coding agents 的可靠性保障
  - 生产级 AI 系统的错误预防
  - 团队 AI 工具的标准化管理
  - 长时间运行 Agent 的自我修正

- **交叉验证**：
  - ✅ OpenAI 发布 Harness Engineering 案例研究
  - ✅ Stripe Minions 系统实践
  - ✅ Anthropic 长时间运行 Agent 有效 Harness
  - ✅ GitHub 1,125+ issues/PRs 讨论
  - ✅ arXiv 论文 "Natural-Language Agent Harnesses"
  - ✅ 中国技术社区（知乎、微信公众号）深度讨论
  - ✅ 多个 GitHub 仓库使用该术语作为描述

- **争议与质疑**：
  - Harness 过度设计可能导致 Agent 灵活性下降
  - 不同场景下 Guides/Sensors 的比例需因地制宜

- **使用场景**：

### Agentic Skills Framework 🔥

- **定义**：一种为 coding agents 构建的软件开发方法论，通过可组合的"技能"（Skills）库实现自动化工作流程。Skills 在相关任务上下文中自动触发（非手动调用），强制 agents 执行 brainstorming、spec 验证、计划分解、TDD 和代码审查等系统性步骤。

- **起源追溯**：
  - **提出者**：Jesse Vincent（obra）与 Prime Radiant
  - **项目**：[obra/superpowers](https://github.com/obra/superpowers)
  - **首次提出**：仓库创建于 2025 年，2026 年 3-4 月快速爆发

- **提出背景**：解决 coding agents "直接跳入编码"的常见问题。通过强制性的 brainstorming 和 spec 验证阶段，确保 agents 在写代码前理解需求；通过细粒度计划（2-5 分钟任务）和自动触发的 Skills，保证工作流程的系统性。

- **使用场景**：
  - 为 AI coding agents（Claude Code、Cursor、Codex 等）提供结构化开发流程
  - 强制 TDD 和代码审查
  - 多 agent 并行开发协调

- **交叉验证**：⚠️ 【未形成独立讨论】— 该术语主要由 superpowers 项目定义和使用，外部独立讨论较少

- **争议与质疑**：
  - "agentic slop" 问题：项目明确提到 94% 的 PR 因质量低下被拒绝
  - 强制性流程可能与某些 agents 的灵活性需求冲突
