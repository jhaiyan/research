### Context Engineering 🔥

- **定义**：一种针对 AI Agent 和 LLM 应用的上游系统工程实践，涵盖上下文的 **Write（写入）、Select（选择）、Compress（压缩）、Isolate（隔离）** 四大核心操作。生产环境中，Prompt 仅占 Agent 上下文预算的 5%，其余 95% 来自检索、记忆、工具调用和架构设计。

- **起源追溯**：
  - **2023 年 1 月 23 日**：**Riley Goodside**（Strike.dev）在 HN 评论中首次命名并系统阐述，将 Prompt Engineering 拆分为 *context engineering*（选择和准备上下文）+ *prompt programming*（编写清晰指令）——这是该术语的最早提出
  - **2025 年 6 月**：Andrej Karpathy 转发 Simon Willison 的推广文章，概念开始广泛传播
  - **2025 年 6 月**：Drew Breunig 提出上下文四大问题类型（poisoning/distraction/confusion/clash）及对应解法（隔离/剪枝/摘要/卸载）
  - **2025 年 11 月**：Matt Webb 提出 **context plumbing** 子概念，聚焦上下文的"搬运和传递"基础设施
  - **2026 年 2 月**：Structured Context Engineering 论文发布（学术系统化）
  - **2026 年 2 月**：Simon Willison 发起 **Agentic Engineering Patterns** 项目，以 1994 年《Design Patterns》为蓝本记录工作模式
  - **2026 年 4 月**：ByteByteGo 文章引发主流传播

- **提出背景**：解决 LLM 应用中上下文管理碎片化问题。传统做法将 Prompt Engineering 局限于措辞优化，而 Context Engineering 将其扩展为涵盖 RAG、记忆系统、工具调用和上下文隔离的完整工程体系。

- **使用场景**：
  - AI Agent 的长期记忆管理
  - 多轮对话的上下文压缩与检索
  - RAG 系统的上下文选择策略
  - Agent 间的上下文隔离

- **交叉验证**：ByteByteGo、Simon Willison、Martin Fowler、Anthropic 官方文档等多个独立来源确认

- **相关链接**：
  - [ByteByteGo: Context Engineering](https://bytebytego.com)
  - [Simon Willison: Context Engineering](https://simonwillison.net)
  - [Anthropic: Context Engineering](https://docs.anthropic.com)

### Harness Engineering 🔥

- **定义**：围绕 AI Coding Agent 设计和构建**约束机制、反馈回路、工作流控制和持续改进循环**的系统工程实践。核心公式：**Agent = Model + Harness**。两个核心组件：**Guides（引导）** 提供前馈控制，**Sensors（传感器）** 提供反馈控制。

- **起源追溯**：
  - **2026 年 2 月 5 日**：**Mitchell Hashimoto**（HashiCorp 联合创始人、Terraform 创作者）首次提出概念
  - **2026 年 2 月 17 日**：**Birgitta Böckeler**（Thoughtworks）发布早期备忘录
  - **2026 年 4 月 2 日**：**Birgitta Böckeler** 在 Martin Fowler 发布完整系统性框架，引入 Guides（前馈）和 Sensors（反馈）双回路模型
  - **2026 年早期**：LangChain 将概念公式化为 **Agent = Model + Harness**

- **提出背景**：解决 AI Coding Agent 在长时间运行中出现重复错误的根本问题。实验数据：仅改变 Harness 而不修改模型权重，编码基准分数可从 6.7% 跃升至 68.3%。

- **使用场景**：
  - AI coding agents 的可靠性保障
  - 生产级 AI 系统的错误预防
  - 团队 AI 工具的标准化管理
  - 长时间运行 Agent 的自我修正

- **交叉验证**：OpenAI 发布 Harness Engineering 案例研究、Stripe Minions 系统实践、GitHub 1,125+ issues/PRs 讨论、arXiv 论文

- **相关链接**：
  - [My AI Adoption Journey - Mitchell Hashimoto (2026-02-05)](https://mitchellh.com/writing/my-ai-adoption-journey)
  - [Harness Engineering - Martin Fowler / Birgitta Böckeler (2026-04-02)](https://martinfowler.com/articles/harness-engineering.html)
  - [arXiv: Natural-Language Agent Harnesses (2603.25723)](https://arxiv.org/abs/2603.25723)

### Agentic Engineering Patterns 🔥

- **定义**：一种以 AI Agent 为核心的系统化工程方法论，涵盖自主规划、工具使用、多步骤迭代执行复杂任务的完整体系。Simon Willison 称其为"过去两年最重要的 AI 概念发展之一"。

- **起源追溯**：
  - **2026 年 2 月 23 日**：**Simon Willison** 在博客首次系统阐述并命名该术语，明确将其作为"专业工程师全面主导"的范式与 vibe coding 对立

- **提出背景**：随着 Claude Code、Cursor 等 AI 编码助手成熟（2025 年 12 月出现能力质变拐点），单纯依靠 prompt 已无法满足复杂任务需求，需要系统化的 Agent 架构设计。

- **使用场景**：自动化代码生成与调试、复杂多步骤任务执行、持续学习与记忆的 AI 系统。

- **相关链接**：
  - [Simon Willison: Agentic Engineering Patterns (2026-02-23)](https://simonwillison.net/2026/Feb/23/agentic-engineering-patterns/)
  - [Karpathy:编码 Agent 能力质变 (2025-12)](https://twitter.com/karpathy/status/1937902205765607626)

### Agent Skills 🔥

- **定义**：可复用、模块化的 AI Agent 功能单元，定义 Agent 可以调用的工具、执行的步骤和预期的输出模式。Skills 在相关任务上下文中自动触发（非手动调用），强制 agents 执行系统性步骤（brainstorming → 规划 → TDD → 代码审查）。

- **提出背景**：随着 Agent 数量增加，如何标准化、可复用地构建 Agent 技能成为关键问题。

- **使用场景**：代码调试自动化、代码审查自动化、测试生成、多 Agent 协作。

### On-device Agentic AI 🔥

- **定义**：一种在用户设备端（如手机、平板、电脑）本地运行的 AI 代理架构，能够自主理解多模态输入（文本/图像/音频/视频），独立决策并调用外部工具（如 Wikipedia、地图 API）完成复杂任务，全程无需云端网络连接。

- **起源追溯**：
  - **2026 年 4 月 2 日**：Google DeepMind 发布 Gemma 4 系列模型，首次在端侧实现完整多模态代理能力
  - **2026 年 4 月 2 日**：Hugging Face 博客以 "Frontier multimodal intelligence on device" 为题介绍

- **提出背景**：解决隐私敏感场景下的 AI 部署需求，同时降低对云端连接的依赖。Gemma 4 通过模型小型化（E2B 2.3B 参数、E4B 4.5B 参数）和高效架构首次在端侧实现复杂代理工作流。

- **使用场景**：
  - 移动设备上的实时多模态理解（拍照提问、语音助手）
  - 离线环境下的工具访问（无网络时查询 Wikipedia）
  - 数据隐私敏感场景（医疗、金融、个人文档处理）
  - 设备控制代理（手机/车载 UI 操作）

- **相关链接**：
  - [Hugging Face Blog: Gemma 4](https://huggingface.co/blog/gemma4)
  - [Google DeepMind Blog: Gemma 4](https://deepmind.google/blog/gemma-4/)

- **定义**：一种为 coding agents 构建的软件开发方法论，通过可组合的"技能"（Skills）库实现自动化工作流程。Skills 在相关任务上下文中自动触发（非手动调用），强制 agents 执行 brainstorming、spec 验证、计划分解、TDD 和代码审查等系统性步骤。

### Vibe Coding vs Agentic Engineering 🌱

- **定义**：AI 辅助编程的两个**对立范式**，位于同一光谱的两端。**Vibe Coding** 强调直觉和感受驱动，对代码完全漠视（"pay no attention to the code at all"），适合非程序员的快速原型；**Agentic Engineering** 强调专业工程师全面主导，系统化、可复用、可测试的工程方法，适合复杂生产任务。

- **起源追溯**：
  - **Vibe Coding**：**Andrej Karpathy**，2025 年 2 月正式命名
  - **Agentic Engineering**：**Simon Willison**，2026 年 2 月 23 日正式命名，明确作为对立范式提出
  - 两者不是演进关系，而是**对待同一现象的两种截然相反的态度**

- **对比**：

| 维度 | Vibe Coding | Agentic Engineering |
|------|-------------|---------------------|
| 提出者 | Andrej Karpathy（2025年2月） | Simon Willison（2026年2月23日） |
| 核心态度 | 对代码完全漠视 | 专业工程师全面主导和审查 |
| 主要受众 | 非程序员快速原型 | 专业软件工程师 |
| 代码质量 | 原型级、未审查 | 生产级、经过工程纪律约束 |
| 定位 | AI 辅助编程的极端化形态 | Vibe Coding 的对立范式 |

- **相关链接**：
  - [GitHub: from vibe coding to agentic engineering](https://github.com/shanraisshan/claude-code-best-practice)
  - [Simon Willison: Agentic Engineering Patterns (2026-02-23)](https://simonwillison.net/2026/Feb/23/agentic-engineering-patterns/)

### Inner Loop vs Outer Loop (Agents) 🌱

- **定义**：**内层循环（Inner Loop）** 指 Agent 执行快速任务响应的循环，延迟要求高，对应即时工具调用和短期任务执行；**外层循环（Outer Loop）** 指 Agent 进行长期规划、学习和自我改进的循环，延迟容忍度高，对应跨任务的经验积累和策略调整。

- **起源追溯**：该二分框架源自软件工程经典模式（IDE 内外循环、游戏引擎帧循环 vs 物理模拟循环），Phil Schmid 将其移植到 Agent 架构语境。**【Phil Schmid URL 返回 404，不可访问，原始来源无法独立核实】**

- **使用场景**：区分 Agent 的即时响应能力和长期学习能力，用于架构设计和性能优化。
