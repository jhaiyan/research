## 摘要

2026 年初是 AI 领域范式转变最密集的时期之一。**Context Engineering**（上下文工程）正式取代 Prompt Engineering 成为新的核心工程学科；**Harness Engineering**（驾驭工程）提出 "Agent = Model + Harness" 公式，将关注点从模型能力转向生产基础设施；**Agentic Engineering**（代理工程）由 Karpathy 正式命名，标志着从 Vibe Coding 到工程化编排的范式跃迁；**Spec Driven Development**（规格驱动开发）和 **Cognitive Debt**（认知债务）分别从方法论和风险维度重新定义了 AI 辅助开发的边界。**Yann LeCun** 离开 Meta 创立 AMI Labs，推动"世界模型"成为继 LLM 之后的下一个架构范式。

模型层面，Claude Opus 4.6、GPT-5.4、Gemma 4、GLM-5.1、Llama 5 先后发布，开源与闭源的差距急剧缩小——GLM-5.1 以 SWE-Bench Pro 58.4 超越 GPT-5.4 和 Claude Opus 4.6。基础设施层面，Anthropic 获 $30B 融资（$380B 估值）、OpenAI 完成 $122B 融资（$852B 估值）、NVIDIA Vera Rubin 七芯片架构发布、MCP 与 A2A 协议双双进入 Linux Foundation。安全层面，Claude Mythos 因网络安全能力过强而被主动 withheld，OpenClaw 安全危机暴露 Agent 安全的一线风险。中国 AI 生态（DeepSeek、Qwen、GLM）在华为昇腾芯片上实现全链条自主，全球 AI 硬件生态出现地缘性分化。

### Context Engineering（上下文工程）🔥

- **定义**：设计、策划和优化 LLM 上下文窗口中整个信息环境的学科——不仅仅是 Prompt，而是模型生成响应时"看到"的所有内容，包括系统指令、检索文档、对话历史、工具定义和任务描述。
- **起源追溯**：概念根源来自 Anind K. Dey（Georgia Tech，2001）对上下文的学术定义。**Tobi Lütke**（Shopify CEO）于 2025 年 6 月称其为"与 AI 协作的最高杠杆技能"。**Andrej Karpathy** 于 2025 年 6 月正式命名并阐述。**Anthropic** 于 2025 年 9 月发布《Effective Context Engineering for AI Agents》参考文档。2026 年初被 LangChain、Princeton 等机构系统化。
- **提出背景**：Prompt Engineering 只关注单条指令的措辞，但生产环境中 Prompt 仅占 Agent 上下文预算的 **5%**，其余 95% 是检索、记忆、工具和架构。2026 年 2 月 McMillan 的同行评审研究（9,649 次实验）发现 Prompt 格式对准确率无统计显著影响（p=0.484），而模型选择造成 21 个百分点的差距。LOCA-bench 研究确认"大多数 Agent 失败不是模型失败，而是上下文失败"。
- **使用场景**：生产 AI Agent 的上下文管理、多轮对话的信息压缩与隔离、RAG 系统的检索优化、Agent Skill 的渐进式加载。
- **四大核心技术**：
  1. **Write** — 在上下文外持久化信息（MEMORY.md、任务日志、Mem0/Letta 记忆数据库）
  2. **Select** — 仅检索相关信息，即时获取（RAG、MCP 协议、5-8 个工具而非全部暴露可提升函数调用 44%）
  3. **Compress** — 减少上下文中的信息量而不丢失关键内容（对话压缩、滑动窗口、Provence 工具实现 95% 压缩率）
  4. **Isolate** — 将工作拆分到独立的专注上下文中（子 Agent 委派、扇出/扇入、Anthropic 多智能体系统提升 90.2%）
- **交叉验证**：Anthropic（官方文档）、LangChain/Sequoia（四支柱框架）、Princeton 研究（Harness 配置提升 64% 解决率）、Martin Fowler（Context Anchoring 系列）、Simon Willison（Agentic Engineering 系列）。
- **争议与质疑**：2026 年 2 月的同行评审研究表明 Context Engineering 并非取代 Prompt Engineering，而是在良好 Prompt 基础上的叠加价值。将 Prompt Engineering 与 Context Engineering 对立是误导性的——Context Engineering 增加了需要良好 Prompt 设计的位置数量。

### Harness Engineering（驾驭工程）🔥

- **定义**：设计和构建 AI 模型运行环境（即 "harness"）的工程学科，涵盖工具编排、验证循环、状态管理、成本控制、可观测性和人机协作控制等全部基础设施层。核心公式：**Agent = Model + Harness** — 模型提供推理能力，harness 决定推理能否转化为可靠输出。换模型输出质量波动 10-15%，换 harness 设计则决定系统是否可用。
- **起源追溯**：术语最早由 **Mitchell Hashimoto**（HashiCorp 联合创始人）于 **2026 年 2 月 5 日**在 ["My AI Adoption Journey"](https://mitchellh.com/writing/my-ai-adoption-journey) 中提出，原文为 *"I've grown to calling this 'harness engineering.'"* 随后 **OpenAI** 于 **2026 年 2 月 11 日**发布 ["Harness Engineering: Leveraging Codex in an Agent-First World"](https://openai.com/index/harness-engineering/)（Ryan Lopopolo），**LangChain** 的 Vivek Trivedy 于 **2026 年 3 月 10 日**发表 ["The Anatomy of an Agent Harness"](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)，**Birgitta Bockeler**（Thoughtworks）于 **2026 年 4 月 2 日**在 Martin Fowler 站点发表 [最系统的理论阐述](https://martinfowler.com/articles/harness-engineering.html)。
- **提出背景**：AI coding agent 从 demo 走向生产，团队发现模型已趋同质化（可互换），而可靠性瓶颈不在模型能力，而在模型周围的执行环境。OpenAI 团队 3 名工程师用 Harness + Codex 在 5 个月内构建了 100 万+ 行生产代码，零人工编写；Vercel 通过将工具从 15 个减至 2 个将准确率从 80% 提升至 100%；LangChain 仅优化 harness 即将 TerminalBench 从 52.8% 提升至 66.5%。共识：**模型是通用商品，harness 才是护城河**。
- **使用场景**：AI coding agent 的生产化部署；长期自主 agent 的验证循环与状态管理；多 agent 协作系统的编排与约束；任何需要将 demo 级 agent 提升为生产级可靠系统的场景。
- **交叉验证**：5 个以上独立来源进行了实质性讨论 — OpenAI 工程博客、LangChain 博客、Martin Fowler、Hacker News 多帖（4 条独立讨论）、Reddit 多社区、dev.to 5 篇文章、GitHub 相关项目、Latent.Space 专题辩论。
- **争议与质疑**：(1) "术语是暂时的" — 部分人预言模型将吞掉 harness；(2) "不是新概念" — SGLang 团队认为只是传统软件工程原则的重新包装；(3) "只保证代码整洁，不保证产品正确" — Birgitta Bockeler 本人指出行为 harness 仍是 "房间里的大象"；(4) "绿场幻觉" — 绝大多数公司面对存量系统，引入 harness 成本极高。

### Agentic Engineering（代理工程）🔥

- **定义**：人类编排自主 AI 智能体编写代码的工程实践，与 Vibe Coding 的关键区别在于强调工程纪律、监督和对质量的零妥协。
- **起源追溯**：由 **Andrej Karpathy** 于 2026 年 2 月提出，他在一年前创造了"Vibe Coding"一词，现在宣布该词"已过时"。原文："Agentic — because the new default is that you are not writing the code directly 99% of the time, you are orchestrating agents. Engineering — because there is an art & science and expertise to it." **Simon Willison** 亦于同期发表 "Agentic Engineering Patterns"（15 章指南），从模式角度系统化了 AI 编码代理的工程化方法论。
- **提出背景**：Vibe Coding 的"70% 问题"（Google 的 Addy Osmani 命名）——AI 快速完成 70% 的工作，但最后 30% 的收益递减导致代码质量问题。CodeRabbit 分析 470 个 GitHub PR 发现 AI 生成代码有 1.7x 更多主要问题和 2.74x 更多安全漏洞。
- **使用场景**：AI 辅助软件开发，特别是多智能体编码、自动化测试、代码审查、架构设计。
- **交叉验证**：Anthropic 2026 智能体编码趋势报告正式采用此范式；Cursor 融资 $2.3B，ARR 超 $1B；Gartner 报告多智能体系统查询暴增 1,445%；Simon Willison 的 Agentic Engineering Patterns 与 Karpathy 的定义形成互补。
- **争议与质疑**：开发者 Andrey Kolkov 提出"Smart Coding"作为超集框架，认为 Agentic Engineering 忽略了双向学习——系统性地通过知识文件让 AI 积累项目上下文。

### Agent-First（Agent 优先）🔥

- **定义**：将 AI Agent 作为软件设计的首要消费者和交互范式，而非将 Agent 功能附加到现有人机界面之上的架构理念。类比 2010 年的 Mobile-First 转型。
- **起源追溯**：**Vikas Sah** 于 2026 年 3 月在 Medium 上发表《Agent-First Is the New Mobile-First》是最早系统阐述此概念的独立文章。**Frequency** 同期发表《The Agent-First Thesis》。Gartner 预测 2026 年底 40% 企业应用将嵌入 Agent 能力。
- **提出背景**：当前大多数企业软件的 API 是为人类开发者设计的，而非为 AI Agent。Agent-First 要求四层新架构：结构化接口层、发现与注册层、Agent 编排层、反馈与奖励层。Gartner 同时警告 40%+ 的 Agent AI 项目将在 2027 年底前被取消。
- **使用场景**：企业 API 重新设计为 Agent 可读、产品 Agent 发现与注册、多 Agent 系统的编排与反馈循环。
- **交叉验证**：Vikas Sah（Medium）、Frequency、SimplAI、Gartner 预测、PwC 调查（79% 高管采纳 AI Agent）、McKinsey Agentic AI Mesh 架构。
- **争议与质疑**：Gartner 警告 40%+ 的 Agent AI 项目将因成本上升、价值不明确或"Agent washing"而被取消。目前大多数企业处于 Agent-First Level 1。

### Spec Driven Development 🌱

- **定义**：一种软件开发方法论，其中自然语言或半结构化规格说明是真实来源和主要工件，代码是由 AI 编码 Agent 根据规格说明和验证测试生成的下游产物。核心颠覆：规格定义"是什么"和"为什么"，AI Agent 实现"如何做"，测试验证一致性。SDD 不是一次性流程，而是持续反馈循环，实现决策反向影响规格。
- **起源追溯**：学术先例为 Ostroff 等人 2004 年 "Agile Specification-Driven Development"。现代 AI 时代术语由 **Drew Breunig** 于 **2026 年 2 月 6 日**在 ["The Rise of Spec Driven Development"](https://www.dbreunig.com/2026/02/06/the-rise-of-spec-driven-development.html) 中正式推广；**John Lam**（GitHub 研究员）的 Spec Kit 项目（2025 年 9 月）是关键工具实现；Thoughtworks、Google Cloud、AWS Kiro 均独立探索。
- **提出背景**：作为 Vibe Coding 的对立面出现。AI 编码 Agent 可快速生成代码，但模糊提示导致意图漂移（"AI drift"）、架构不一致。代码生成变得廉价，但错误架构仍然昂贵。规格作为人类意图与 AI 执行之间的压缩、明确的契约。
- **使用场景**：绿地项目（从规格定义整个应用）；移植和仿真（参考实现提供测试地面真相，是最高价值用例）；棕地功能工作；遗留现代化。
- **交叉验证**：Hacker News 4+ 独立讨论、Reddit 5+ 帖子、Medium 5+ 篇文章、GitHub Spec Kit 85K+ 星、Thoughtworks 技术雷达收录、Martin Fowler 站点专文。工具生态已成型：GitHub Spec Kit、AWS Kiro、Tessl、Windsurf Plan Mode。
- **争议与质疑**：(1) "回归瀑布模型" — 用 Markdown 代替 UML 图表的 BDUF？(2) "Markdown 规格不可靠" — Agent 经常忽略非结构化文本；(3) "过度工程化" — Kiro 将一个小 bug 变成 4 个用户故事和 16 个验收标准；(4) "棕地差距" — 当前工具对绿地项目最有效，存量代码库指导很少。

### Cognitive Debt / Intent Debt 🌱

- **定义**：**认知债务**（Cognitive Debt）：团队对系统的共享理解（心智模型）的流失速度超过补充速度所累积的隐性成本，"存在于人身上"。**意图债务**（Intent Debt）：指导系统演化的目标、约束和决策理由未能被显式捕获或维护所累积的债务，"存在于产物中"。**三层债务模型**：技术债务（代码）→ 认知债务（人）→ 意图债务（产物），三者相互作用、相互强化。
- **起源追溯**："认知债务" 最早由 **John V Willshire**（Smithery Ltd.）于 **2025 年 4 月 25 日**提出；"意图债务" 及三层模型由 **Margaret-Anne Storey**（University of Victoria）于 **2026 年 3 月 23 日**在 arXiv 论文 [arXiv:2603.22106](https://arxiv.org/abs/2603.22106) 中正式提出；**Martin Fowler** 于 **2026 年 4 月 2 日**在其 Fragments 博文中推广该框架。哲学根基为 Peter Naur 1985 年经典论文 "Programming as Theory Building"。关联理论：Shaw & Nave（Wharton）"认知投降 vs. 认知卸载"三系统理论。
- **提出背景**：AI 代码生成使代码生产速度远超人类理解速度，产生传统技术债务框架无法描述的新问题：代码能运行、测试能通过，但无人理解为何如此设计。当 Ona 公司 88.5% 的 PR 由 AI 生成时，团队的集体心智模型被侵蚀。AI 减少了技术债务，却加速了认知债务和意图债务。
- **使用场景**：AI 辅助开发项目的健康度评估；团队能力衰退诊断；AI Agent 可维护性评估；识别哪些领域应设为 "AI-free zones"（认证、支付、数据删除）；开发者个人认知健身。
- **交叉验证**：Hacker News 主帖 710 points / 511 comments；Reddit 多子版讨论；Medium 5+ 篇独立文章（含 Addy Osmani "Comprehension Debt"）；DEV Community 多帖；GitHub 开源 [cognitive-debt-prevention-kit](https://github.com/kesslernity/cognitive-debt-prevention-kit)。
- **争议与质疑**：(1) Martin Fowler 本人对 "债务隐喻的扩散感到困惑"；(2) MIT EEG 研究被神经科学家质疑为 "伪科学"（样本量小、作者利益关联）；(3) "认知衰退可能不是可偿还的债务，而是不可逆的认知临界点" — HN 高赞评论指出 "这是一个没有版本控制的用进废退系统"。

### World Models 🌱

- **定义**：能够构建物理/因果现实内部表征并预测世界下一状态的 AI 系统，与 LLM 预测下一 token 形成根本区别。
- **起源追溯**：**Yann LeCun** 长期倡导，2025 年底离开 Meta 创立 **AMI Labs**（$10.3 亿融资，欧洲史上最大种子轮），2026 年 3 月与 Mila、NYU、Samsung SAIL 合作发表 **LeWorldModel (LeWM)**，解决了 JEPA 架构的表示坍塌问题。Fei-Fei Li 的 World Labs 于 2026 年 1 月发布 **Marble**——首个商业世界模型 API。
- **提出背景**：LLM 是"黑暗中的文字工匠"——流畅但物理不接地。LeCun 在 Davos AI Summit 2026 称在 LLM 上构建自主智能体是"灾难配方"。Ilya Sutskever、Richard Sutton 等均认同 LLM 面临根本性限制。
- **使用场景**：机器人导航与操控、自动驾驶、游戏模拟、物理推理、具身 AI。
- **交叉验证**：Google DeepMind 的 Genie 3、NVIDIA Cosmos 平台、DreamerV3（Nature 发表）、Vid2World（ICLR 2026）均从不同角度验证世界模型方向。IBM 预测 2026 年是"世界模型之年"。
- **争议与质疑**：LeCun 的 JEPA 架构在 LeWM 之前长期受"表示坍塌"困扰；世界模型是否能在复杂开放世界场景中保持可靠仍是开放问题；部分研究者认为 LLM + 世界模型的混合架构更可行。

### Verification-Centric Reasoning 🌱

- **定义**：一种 Agent 推理架构范式，核心主张是"验证使 Agent 更快而非更慢"。在推理的中间步骤（Local Verifier）和完整轨迹（Global Verifier）两个层面嵌入显式验证机制，强制 Agent 在每一步寻找 **证伪证据** 而非沿最高概率路径贪心推进，从而同时提升准确率并大幅减少无效交互步骤。
- **起源追溯**：由 **MiroMind Team** 在论文 [arXiv:2603.15726](https://arxiv.org/abs/2603.15726v1)（2026-03-16）中首次系统提出。两周后，阿里巴巴的 Bin Zhu 等人在 [arXiv:2603.28376](https://arxiv.org/abs/2603.28376)（2026-03-30）中独立采用同一术语，印证了该概念的扩散趋势。
- **提出背景**：当前 Agent 普遍采用"暴力交互扩展"策略 — 更多步骤、更长上下文、更多工具调用。但无验证的交互扩展产生大量无效步骤（pathological looping），既浪费计算又累积错误。MiroThinker 的 Local Verifier 将交互步骤从 ~1,200 降至 ~210（82% 削减），Global Verifier 在 BrowseComp 上额外增加 +14 分。
- **使用场景**：长程开放网页研究（BrowseComp SOTA 88.2）；科学推理；金融分析；任何需要多步推理且错误会逐级传播的 Agent 场景。
- **交叉验证**：r/MachineLearning 讨论帖、PR Newswire 官方公告、Marco DeepResearch 独立采用、ToKnow.ai 博文、MiroMind 官方博客。但 HN 未发现相关讨论。
- **争议与质疑**：(1) 基线是否存在病态循环？部分改善可能是在修正退化行为而非范式突破；(2) H1 权重未开源，关键消融实验无法独立复现；(3) 自验证的固有局限 — 学术研究表明 LLM 自我批评可能导致性能崩溃；(4) BrowseComp 从 16x 到 64x 计算量仅提升 ~2 分，暗示验证策略本身也存在 scaling ceiling。
- **相关链接**：
  - [MiroThinker 论文 (arXiv)](https://arxiv.org/abs/2603.15726v1)
  - [Marco DeepResearch (后续采用者)](https://arxiv.org/abs/2603.28376)
  - [GitHub 仓库](https://github.com/MiroMindAI/MiroThinker)

### Societies of Thought 🌱

- **定义**：指高级推理模型在推理过程中自发模拟的多 Agent 式内部辩论结构 — 由具备不同人格特质和领域专长的内部认知视角相互质疑、冲突与调和，从而实现比单链条计算更优的问题求解。该概念认为推理能力的提升并非仅靠"思考更久"，而是靠内部多样化的"社会性"辩论与协作。
- **起源追溯**：由 **Junsol Kim、Blaise Agüera y Arcas、James Evans** 等人在论文 ["Reasoning Models Generate Societies of Thought"](https://arxiv.org/abs/2601.10825)（arXiv:2601.10825，2026-01-15）中正式提出。作者来自 Google Paradigms of Intelligence Team、University of Chicago、Santa Fe Institute。
- **提出背景**：传统观点认为推理模型的优势在于生成更长的思维链（CoT），即更长的计算。但该研究发现推理模型在思维链中自发产生问答、视角转换、冲突与和解等对话行为，且这些行为的增加与问题难度正相关。RL 仅奖励准确性即可使模型自发发展出内部对话行为。超过 20% 的准确率优势由社会/对话行为中介。
- **使用场景**：推理模型机制可解释性研究；训练策略优化（对话脚手架替代独白脚手架可加速 RL 学习）；激活引导（定向增强"对话惊讶"特征可将准确率翻倍）；多 Agent 系统设计；AI 对齐（从个体 RLHF 转向制度性对齐）。
- **交叉验证**：LessWrong 深度分析文、Coffee with Claude 独立复现（SOCRATES 系统）、EmergentMind 77 条推文约 14,970 赞、alphaXiv 202 赞同票。但 HN 两次提交仅获 2-3 点赞，Reddit 无直接讨论帖。
- **争议与质疑**：(1) LessWrong 评论者指出论文谨慎使用"视角"而非"人格"，内部究竟是真实多 Agent 结构还是习得的表面对话模式，证据无法区分；(2) "思想社会是必要但不充分的" — 多样性不代表推理，社会系统同样可产生从众和合理化；(3) 代码、提示和 SAE 权重尚未公开，可复现性受限。
- **相关链接**：
  - [Reasoning Models Generate Societies of Thought (arXiv)](https://arxiv.org/abs/2601.10825)
  - [LessWrong 深度分析](https://www.lesswrong.com/posts/juLewpYdGJEL2JCkb/a-closer-look-at-the-societies-of-thought-paper)

### Evolution Engineering 🌱

- **定义**：设计 AI 能力通过进化机制而非人工工程自我改进的系统，核心元素包括基因（可迁移能力单元）、适应度函数、竞技场（竞争评估）和水平逻辑转移。
- **起源追溯**：由 **Rotifer 团队**于 2026 年 3 月在 [rotifer.dev](https://rotifer.dev/blog/evolution-engineering) 正式定义。灵感来自蛭形轮虫的基因水平转移机制。
- **提出背景**：AI 工程栈经历了 Prompt Engineering → Context Engineering → Harness Engineering 的演进，但能力的生命周期管理（创建、评估、优化、传播）仍为空白。
- **交叉验证**：Amazon 的 A-Evolve 框架（2026 年 3 月）独立实现了类似概念——5 阶段进化循环，在 MCP-Atlas 达到 79.4%。MiniMax M2.7 也展示了 100+ 自主优化轮次、30% 性能提升的自进化智能体。但 Rotifer 自我定位为"stage 0.5"——基础已建立，但生态级验证仍在路上。
- **相关链接**：

  - [A-Evolve: The PyTorch Moment for Agentic AI Systems](https://www.marktechpost.com/2026/03/29/meet-a-evolve-the-pytorch-moment-for-agentic-ai-systems/)

## 开发范式

### 从 Prompt Engineering 到 Harness Engineering 的五层演进

2026 年初的 AI 工程栈可清晰地划分为五个递进层次：

| 层级 | 范式 | 核心问题 | 时间段 |
|------|------|----------|--------|
| 1 | Prompt Engineering | 如何与 AI 对话 | 2022-2024 |
| 2 | Context Engineering | AI 需要知道什么 | 2025 |
| 3 | Harness Engineering | 如何让 AI 可靠执行 | 2025-2026 |
| 4 | Agentic Engineering | 如何编排自主智能体 | 2026 |
| 5 | Evolution Engineering | 如何让能力自我进化 | 2026- |

**关键洞察**：同一模型在不同 Harness 下性能差距可达 6 倍（Claude Opus 4.5 在一个 Harness 中得分 2%，在另一个中得分 12%）。**模型已是基础设施，工程才是护城河**。

### Context Engineering 的四大操作

2026 年行业共识收敛于 **Write · Select · Compress · Isolate** 四大操作：

1. **Write** — 外部持久化：MEMORY.md 刮擦板、结构化任务日志、记忆数据库（Mem0, Letta）
2. **Select** — 即时检索：RAG + 动态工具加载（5-8 个工具，而非全部暴露，可提升函数调用 44%）
3. **Compress** — 无损压缩：对话压缩（Claude Code 在 95% 容量自动压缩）、滑动窗口 + 锚点、Provence 工具实现 95% 压缩率
4. **Isolate** — 跨智能体隔离：子智能体委派、扇出/扇入、上下文隔离（Anthropic 多智能体系统提升 90.2%）

### 上下文的四种失败模式

Chroma Research 测试 18 个前沿模型发现**每一个**都在更长的上下文下退化：

| 失败模式 | 描述 | 证据 |
|----------|------|------|
| 上下文中毒 | 幻觉进入上下文被当作事实，错误级联 | Gemini Pokémon 智能体持续整个会话的虚假游戏状态 |
| 上下文分心 | 累积历史淹没训练知识 | Llama 3.1 405B 在 ~32K token 后准确率下降 |
| 上下文混淆 | 无关信息影响决策 | Llama 3.1 8B 在 46 个工具时失败，19 个时成功 |
| 上下文冲突 | 冲突的上下文部分导致推理错误 | o3 从 98.1% 降至 64.1%（多轮基准） |

### Agent 架构的六大生产模式

| 模式 | 适用场景 | 关键特征 |
|------|----------|----------|
| ReAct | 简单工具问答（1-5 步） | 交替思考与工具调用 |
| Plan-and-Execute | 复杂多步任务（5+ 步） | 先规划后执行，可重规划 |
| Router Agent | 多用途助手 | 意图分类后路由到专家 |
| Hierarchical | 报告生成、复杂分析 | 管理者分解任务，工作者并行执行 |
| Reflection | 高精度/监管输出 | 自我批判与修正，2-3x 成本但捕获幻觉 |
| State Machine | 明确定义的工作流 | 最可预测/可审计 |

**反模式警告**："上帝智能体"——一个拥有 30+ 工具的巨型智能体。超过 8-10 个工具时应使用 Router 或 Hierarchical 模式。

### AI 辅助开发的四档框架

1. **补充（Supplement）**：AI 提供建议，人类决定是否采纳
2. **集成（Integrate）**：AI 嵌入工作流，人类审批
3. **委派（Delegate）**：AI 自主执行，人类审查结果
4. **编排（Orchestrate）**：上下文即工作，定义 *什么* 和 *为什么*，而非 *如何*

当前行业共识：瓶颈已从"编写代码"转移至"审查和指导代码"。代码审查时间是新的稀缺资源（PR 审查时间增加 91%）。

### AGENTS.md 成为新兴约定

[AGENTS.md](https://www.agents.md/) 是开放的 Markdown 标准，为 AI 编码 Agent 提供项目特定的指令、编码约定、构建命令和测试要求——本质上是"给机器人看的 README"。**OpenAI** 于 2025 年 8 月首次发布，2025 年 12 月 **Linux Foundation** 宣布成立 **Agentic AI Foundation（AAIF）**，AGENTS.md 与 MCP 一同被捐赠给 AAIF。目前 60,000+ 开源仓库采用，10+ 主流编码工具支持。

Phil Schmid 发布的 [AGENTS.md 最佳实践](https://www.philschmid.de/writing-good-agents)：保持 300 行以下、仅人类编写（自动生成的文件降低成功率 ~3%）、工具被提及后使用率增加 160 倍。

### Human-in-Control vs. Human-in-the-Loop

**Human-in-the-Loop** 在每步等待人类审批，制造瓶颈抵消 Agent 速度优势。**Human-in-Control** 重新定义关系：人类监督策略，Agent 执行——而非 Agent 在每一步等待人类批准。

## 方法与技术

### 新架构：超越 Transformer

- **Mamba-3**（Cartesia，2026 年 3 月）：引入指数梯形离散化、复值 SSM 和 MIMO 公式，状态大小减半，解码延迟最低
- **Gated Sparse Attention (GSA)**（Amazon/UC Berkeley，2026 年 1 月）：结合 DeepSeek 稀疏注意力和门控机制，128K 上下文下 12-16 倍加速

### 高效推理

- **Draft-Thinking**：通过渐进式课程学习保留关键步骤，减少 82.6% 推理预算，仅损失 2.6% 准确率

- **TinyLoRA**（Meta FAIR）：仅 13 个可训练参数在 Qwen2.5-7B 上达到 91.8% GSM8K
- **MegaTrain**：单 GPU 训练 100B+ 参数模型，参数/优化器状态存储在 CPU RAM

### NVIDIA PivotRL：4x 更少的训练回合

NVIDIA 于 2026 年 3 月发布 **PivotRL**，填补 SFT 与端到端 RL 之间的差距：
- **Pivot 过滤**：识别"枢纽"——动作方差最高的关键中间回合
- **功能性奖励**：替代精确字符串匹配，允许功能等价的多个动作获得奖励
- 结果：与端到端 RL 相当的准确度，但 **4x 更少的训练回合，5.5x 更快的训练时间**
