## 摘要

本期（2026-06-08 至 2026-06-22）AI 工程领域最显著的叙事转向是：**Agent 开发正从“写提示”迁移到“设计系统”**。以 **Loop Engineering（循环工程）**、**Agent Harness / Harness Engineering** 和 **Agent Skillization（Agent 技能化）** 为代表的新方法论，正在把工程师的杠杆点从单次 prompt 提升到可复用、可验证、可治理的 Agent 系统层。同一时期，Anthropic 的 Claude Fable 5 / Mythos 5 因美国政府出口管制被全面暂停访问，引发对前沿模型治理与 AI 主权的激烈讨论；智谱 GLM-5.2、Google DiffusionGemma、OpenAI Codex Record & Replay 等产品密集发布，开源与闭源模型的差距进一步缩小。

## 本期最值得关注

1. **Loop Engineering / Loopcraft 爆发**：从 Addy Osmani 命名到 LangChain、Cloudflare、Latent Space 等多方跟进，"设计循环系统来自动提示 Agent" 成为 6 月最热的工程范式。
2. **Agent Harness 成为共识**：Anthropic、OpenAI、LangChain、Cloudflare、Databricks 不约而同地使用 "Agent = Model + Harness" 框架，竞争焦点从模型上移到 harness 层。
3. **Agent Skills 生态井喷**：GitHub Trending 上 skill 仓库占据前排，NVIDIA 推出 SkillSpector 安全扫描器，OpenAI Codex 将工作流录制为可复用 skill。
4. **Anthropic Fable 5 / Mythos 5 被美国政府暂停访问**：6 月 12 日美国以国家安全为由要求 Anthropic 暂停两款模型全部访问，引发学术界与业界联名反对。
5. **智谱 GLM-5.2 开源并冲击开源榜首**：744B/40B active MoE、1M 上下文、MIT 许可证，在 FrontierSWE、SWE-Marathon 等长程编码基准上接近 Claude Opus 4.8。

### Loop Engineering / Loopcraft 🔥

- **定义**：设计一套能自动提示 Agent、验证结果、反馈迭代并在满足终止条件时停止的循环系统，使工程师从“手动写 prompt”转变为“设计让 Agent 自我驱动的系统”。一个实用循环至少包含触发/调度、行动、验证/反馈、持久化记忆、终止条件。
- **起源追溯**：术语由 Google 工程总监 **Addy Osmani** 于 2026-06-07 在博客 [Loop Engineering](https://addyosmani.com/blog/loop-engineering/) 中正式命名；核心观念更早由 Anthropic Claude Code 负责人 **Boris Cherny**（2026-06-02 WorkOS 访谈）和 OpenClaw 创始人 **Peter Steinberger**（2026-06-07 X 帖子）公开表达。近义词 "Loopcraft" 由 Latent Space / Swyx 在 2026-06-12 的通讯 [Loopcraft: The Art of Stacking Loops](https://www.latent.space/p/ainews-loopcraft-the-art-of-stacking) 中推广。
- **提出背景**：随着 Claude Code `/loop` / `/goal`、OpenAI Codex Automations、MCP connectors、sub-agents 等产品能力成熟，工程师发现真正的杠杆不在于单次提示的质量，而在于如何设计可扩展、可验证、可自我改进的循环结构。
- **使用场景**：夜间自动化代码重构、持续监控与修复、定时研究报告合成、长期运行的事件响应、自我改进的编码 Agent 等。
- **交叉验证**：LangChain（2026-06-16）将 loop engineering 产品化为四层循环栈；LangWatch 提出循环工程本质是测量问题；Data Science Dojo 梳理了 10 种 loop 类型；多家独立博客（Lushbinary、ExplainX、Puppyone）提供实践指南。
- **争议与质疑**：【有争议】Centerbit 等批评者认为底层思想（cron + 反馈控制）并不新，2026 年的新东西是产品化能力；成本失控风险被多次提及（未设硬停止的循环可能一夜烧掉大量 token）；Saulius 等警告“outsourcing understanding”会侵蚀工程师的深层判断能力；Gartner 将 agentic AI 置于 hype peak，预测 40% 以上 agentic AI 项目将在 2027 年底前被取消。

### Agent Harness / Harness Engineering 🔥

- **定义**：Agent 中除模型本身之外的全部运行时层，包括工具调用、上下文管理、记忆、反馈循环、沙箱、权限、成本/预算控制、可观测性、治理与审批等。最广为引用的公式是 **Agent = Model + Harness**。
- **起源追溯**："agent harness" 在公开 AI-agent 语境下的最早使用可追溯至 Anthropic 2025-09-29 的博客 [Building agents with the Claude Agent SDK](https://www.anthropic.com/engineering/building-agents-with-the-claude-agent-sdk)，其中把 Claude Code SDK 称为 "agent harness"。学科名称 **"Harness Engineering"** 则由 Mitchell Hashimoto 于 2026-02-05 提出，OpenAI 在 2026-02-11 的博客 [Harness engineering: leveraging Codex in an agent-first world](https://openai.com/index/harness-engineering/) 中将其正式确立为工程学科。
- **提出背景**：模型能力快速商品化，同一模型在不同 harness 下的表现可能相差数倍；企业更关注如何让 Agent 在生产环境中可靠、可治理、可审计地运行。
- **使用场景**：生产级 coding agent、长时程任务执行、多 Agent 协作、受监管行业（金融、医疗、航空）的 Agent 部署。
- **交叉验证**：Martin Fowler / Birgitta Böckeler（2026-04-02）提出 Guides（前馈控制）与 Sensors（反馈控制）框架；LangChain（2026-05-21）系统定义 Agent Harness  anatomy；Databricks（2026-06-17）给出生产级 harness 八大构件；Cloudflare（2026-06-17）提出 framework → harness → runtime 三层栈；学术预印本 [Agent Harness for LLM Agents: A Survey](https://www.preprints.org/manuscript/202604.0428/v1)（2026-04-28）将其形式化。
- **争议与质疑**：【有争议】批评者认为 harness engineering 只是“系统软件工程/测试 harness/CI/CD”换了个新名字（Marko Lukičić、Akshay Kokane）；有观点认为 harness 会成为比模型更深层的 vendor lock-in 层（Focused.io、LangChain Model Neutrality）；云原生/分布式系统中的反馈循环难以真正闭环（The New Stack、Ignorance.ai）；自动生成 harness 配置未必提升性能，反而可能增加成本（ETH Zurich、Chroma Research）。

### Agent Skillization / Agent Skills 🔥

- **定义**：将 Agent 的能力/组织经验封装为离散、可复用、可挂载、可治理的“技能单元”，通常以 `SKILL.md` 文件为载体，Agent 可按需动态加载。中文语境中的“Agent Skillization（Agent 技能化）”是对 Anthropic 发起的 Agent Skills 范式在行业扩散现象的概括。
- **起源追溯**：当代 LLM Agent 语境下 "Agent Skills" 的完整概念（文件夹 + `SKILL.md` + 渐进式披露 + 跨平台可移植性）最早由 **Anthropic** 于 2025-10-16 在产品公告 [Introducing Agent Skills](https://www.anthropic.com/news/skills) 和工程博客 [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) 中完整定义。2025-12-18 Anthropic 将其发布为[开放标准](https://agentskills.io/specification)，OpenAI、Microsoft、Cursor 等迅速跟进。
- **提出背景**：当 Agent 从“演示”走向“生产”，团队需要把领域知识、最佳实践、安全规则沉淀为可复用工件，而不是每次重新提示。
- **使用场景**：编码规范审查、安全审计、IaC 合规、发布文档生成、事件响应、视频制作、项目管理、网络安全分析等垂直任务。
- **交叉验证**：OpenAI Codex（2026-06-20）将用户演示工作流录制为可复用 skill；NVIDIA 推出 [SkillSpector](https://github.com/NVIDIA/SkillSpector) 对 Agent Skills 进行安全扫描；Microsoft Azure Databricks 官方文档采用 Agent Skills 标准并提供 `npx skills` CLI；arXiv 综述 [Agent Skills for Large Language Models](https://arxiv.org/html/2602.12430v4) 系统梳理其架构；GitHub Trending 上多个 skill 仓库同时上榜。
- **争议与质疑**：【有争议】术语同名异物问题严重（prompt 包、tool wrapper、工作流编排都被叫做 skill）；不同 Agent 客户端采用不同文件约定导致格式战争；skills 的稳定性受模型版本和框架变更影响；上下文膨胀与“提示词膨胀”风险；安全与供应链风险（OpenClaw ClawHavoc 事件发现 341 个恶意 skills）；有分析认为 Agent Skills 只是过渡层而非最终抽象（OSSInsight）；劳动者主体性反思认为 skillization 可能将隐性知识标准化，削弱高技能人类劳动力价值。
