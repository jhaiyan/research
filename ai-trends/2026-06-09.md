### Tokenomics 🔥

- **定义**：AI 经济学（Tokenomics）是指对 AI 系统中 token 消耗、计量、成本管理和优化的研究与实践。
- **起源追溯**：Linux Foundation 近期宣布成立 **Tokenomics Foundation**，旨在建立类似 Cloud FinOps 的 AI 消费标准化体系。
- **提出背景**：Agentic AI 特性导致每位开发者 AI 消耗量 9 个月内增长 **18.6 倍**，企业预算迅速耗尽。Uber 等公司 2026 预算 4 月即用完，一名工程师单月 token 花费达 $40,000。
- **使用场景**：企业内部 AI 成本监控、供应商计费对账、Token消费优化。
- **交叉验证**：Linux Foundation、AWS FinOps 团队、多家 AI 成本监控初创公司（Pay-i、Paid）均提及此概念。
- **相关链接**：
  - [The Batch #356 - Qwen3.7-Max Challenges Google](https://www.deeplearning.ai/the-batch/issue-356)
  - [TechCrunch - The Token Bill Comes Due](https://techcrunch.com/2026/06/05/the-token-bill-comes-due-inside-the-industry-scramble-to-manage-ais-runaway-costs/)

### Agentic AI 🔥

- **定义**：以自主 AI Agent 为核心特性的 AI 系统，具备规划、工具使用、多步骤推理能力。
- **起源追溯**：OpenAI、Anthropic、Google 均将 Agentic 能力作为2026 年模型升级重点。
- **提出背景**：Perplexity 推出「Search as Code」实现 85% token 成本降低；Google Gemini 3.5 Flash 重点强化 Agentic 能力（APEX-Agents-AA 47.1%，MMMU-Pro 84%）。
- **使用场景**：自动化多步骤任务、自主研究、数据处理流水线。
- **相关链接**：
  - [TechCrunch - Perplexity Search as Code](https://techcrunch.com/2026/06/07/perplexitys-search-as-code-lets-ai-models-write-custom-search-pipelines/)
  - [The Batch #355 - Gemini 3.5 Flash](https://www.deeplearning.ai/the-batch/issue-355)

### Forward Deployed Engineer (FDE) 🌱

- **定义**：嵌入客户组织，现场构建和定制 Agent 工作流的工程师角色。
- **起源追溯**：OpenAI、Anthropic 等公司在硅谷推行此岗位。
- **提出背景**：Andrew Ng 预测 AI Engineer 角色数量将远超 FDE，AI 工程将进一步细分为 LLMOps Engineer、Evals Engineer、AI Data Engineer 等专业方向。
- **使用场景**：企业客户 AI 集成、定制化 Agent 开发。
- **相关链接**：
  - [The Batch #355 - Andrew Ng on AI Engineering Careers](https://www.deeplearning.ai/the-batch/issue-355)

### Context Engineering 🔥

- **定义**：对 AI 系统中上下文（Context）进行结构化管理的新兴学科，超越传统 Prompt 工程，涉及持久化上下文文件（CLAUDE.md、AGENTS.md、.cursorrules）的设计、维护与失效检测。
- **起源追溯**：arXiv 论文 [Context Rot in AI-Assisted Software Development (2606.09090)](https://arxiv.org/abs/2606.09090) 首次系统定义此问题。
- **提出背景**：研究发现 23% 的代码仓库存在上下文文件引用过时代码的问题。LangChain 提出「Latent Context Language Models (LCLMs)」作为架构解决方案。
- **使用场景**：AI 辅助编程工具的上下文管理、企业级 Agent 系统设计。
- **相关链接**：
  - [arXiv:2606.09090 - Context Rot](https://arxiv.org/abs/2606.09090)
  - [arXiv:2606.08867 - Building Customer Support AI Agents at 100M-User Scale](https://arxiv.org/abs/2606.08867)

### Context Rot🌱

- **定义**：持久化上下文文件（CLAUDE.md、AGENTS.md、.cursorrules）随着软件代码的演化而变得过时失效的问题。
- **起源追溯**：arXiv:2606.09090 首次识别和命名此问题。
- **提出背景**：在 23% 的被检代码仓库中，上下文文件存在对过时代码元素的引用。
- **使用场景**：AI 编程助手的上下文维护、代码仓库健康检测。
- **相关链接**：
  - [arXiv:2606.09090 - Context Rot](https://arxiv.org/abs/2606.09090)

### Agent Scaffold 🔥

- **定义**：Agent 的基础设施层，包括工具循环（tool loops）、记忆库（memory banks）、Harness（评估框架）、反思步骤（reflection steps）等原语。
- **起源追溯**：多篇 arXiv 论文（2606.02644、2605.10754、2605.27898）系统阐述此范式。
- **提出背景**：研究显示「Agentic scaffolds 大幅提升了 LLM 在复杂长期任务上的表现」，scaffold 的选择直接影响基准测试结果。
- **使用场景**：Agent 开发框架、多步推理任务、自主研究系统。
- **相关链接**：
  - [arXiv:2606.02644 - A New Framework for Cybersecurity Refusals](https://arxiv.org/abs/2606.02644)

### Model Context Protocol (MCP) 🔥

- **定义**：AI Agent 与外部工具/上下文集成的标准化协议，实现跨系统协作、任务解耦和知识复用。
- **起源追溯**：arXiv:2606.09182 及 GitHub MCP topics。
- **提出背景**：被誉为「AI 界的 USB-C」，正在成为 Agent 工具集成的行业标准。但受生态系统碎片化和协调困难约束。
- **使用场景**：Agent 工具生态集成、跨平台协作。
- **相关链接**：
  - [arXiv:2606.09182 - Understanding How Enterprises Adopt MCP](https://arxiv.org/abs/2606.09182)
  - [GitHub MCP Topics](https://github.com/topics/mcp)

### Multi-Agent Orchestration 🔥

- **定义**：多 Agent 协调编排模式，实现自主任务分解、协作与执行。
- **起源追溯**：arXiv 多篇论文（2606.09122、2606.08878）及 Phil Schmid 博客文章。
- **提出背景**：在网络运维场景中，多 Agent 协调实现超过 90% 的自主解决率。基于规则的测试时优化（rubric-based optimization）用于特定任务质量标准。
- **使用场景**：网络自动化运维、自主事故响应、多步骤研究任务。
- **相关链接**：
  - [arXiv:2606.09122 - Autonomous Incident Resolution](https://arxiv.org/abs/2606.09122)
  - [Phil Schmid - Four Subagent Patterns in 2026](https://www.philschmid.de/how-agents-manage-other-agents-four-subagent-patterns-2026)

### AI Memory Systems 🔥

- **定义**：双层记忆架构，统一语义记忆、情景记忆和程序性记忆，记忆中心设计正在取代 LLM 中心设计。
- **起源追溯**：arXiv:2606.06787 (AdMem)、2606.09659 (Memory Beyond Recall)、Rosetta Memory 等多篇论文。
- **提出背景**：记忆系统正在成为 Agent 架构核心，实现跨模型兼容性。分层图记忆和 Agent检索机制用于长视频理解。
- **使用场景**：长期记忆 Agent、跨会话一致性、多模态理解。
- **相关链接**：
  - [arXiv:2606.06787 - AdMem: Advanced Memory for Task-solving Agents](https://arxiv.org/abs/2606.06787)
  - [GitHub - Deep Memory](https://github.com/TjWheeler/deep-memory)

### SkillBank 🌱

- **定义**：程序性记忆编译机制，Skill 作为可重用可组合的 Agent 开发单元。
- **起源追溯**：LangChain Blog、arXiv:2606.09365 (Anything2Skill)。
- **提出背景**：Self-evolving scene-aware skills 将工具利用率从 39% 提升至 78%。Skill 编译机制实现经验向可执行技能的转化。
- **使用场景**：Agent 技能市场、跨任务技能复用、专业领域 Agent 开发。
- **相关链接**：
  - [LangChain - Building workflows for agents with Skills and Interpreters](https://www.langchain.com/blog/building-workflows-for-agents-with-skills-and-interpreters)
  - [Phil Schmid - 8 Tips for Writing Agent Skills](https://www.philschmid.de/8-tips-for-writing-agent-skills)

### Agentic Harness🌱

- **定义**：区别于模型本身的 Agent 评估框架，将 scaffold（脚手架）与模型解耦评估。
- **起源追溯**：arXiv:2606.07462 (Act As a Real Researcher)。
- **提出背景**：研究显示「scaffold 的选择和环境波动性直接影响基准测试结果」，需要将评估框架与模型分开考量。
- **使用场景**：Agent 基准测试、模型对比评估、Harness 设计优化。
- **相关链接**：
  - [arXiv:2606.07462 - Act As a Real Researcher: Benchmarks for Frontier LLMs](https://arxiv.org/abs/2606.07462)

### AQL (Agent Query Algebra) 🧪

- **定义**：作为 Agent 编排替代方案的结构化查询代数（Structured Query Algebra）。
- **起源追溯**：arXiv:2606.09659。
- **提出背景**：论文指出「Enterprise AI 不是 Prompt 工程问题，而是系统问题」，提出 AQL 作为替代方案。
- **使用场景**：企业级 Agent 查询语言、复杂任务分解。
- **相关链接**：
  - [arXiv:2606.09659 - End-to-End Context Compression at Scale](https://arxiv.org/abs/2606.09659)
