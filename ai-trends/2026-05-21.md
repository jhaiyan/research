### Agent Skills 🔥

- **定义**：一种规范化AI智能体能力扩展的机制，通过SKILL.md文件定义技能的触发条件、执行指令和可选资源，使智能体能够在特定场景下调用预定义的专业能力。
- **起源追溯**：概念无单一发明者，逐步从多个研究团队演化而来。**Toolformer论文**（arXiv:2302.04761，2023年2月9日）奠定了将外部工具作为智能体能力的理论基础；**Voyager论文**（2023年5月）首次明确提出"ever-growing skill library"概念；2025-2026年期间"Agent Skills"术语被广泛采用。
- **提出背景**：随着AI Agent在生产环境中的应用，开发者需要一个可复用、可组合的能力定义标准。SKILL.md的格式化结构解决了"如何让Agent知道何时使用某项能力"的问题。
- **使用场景**：企业级AI Agent开发、跨团队能力共享、垂直领域专业化Agent构建
- **交叉验证**：CrewAI（Skills模式）、Microsoft Semantic Kernel（Plugins/Functions）、Microsoft .NET Agent Skills（三种创作方式）、TechCrunch均有独立报道
- **争议与质疑**：触发机制脆弱性（描述模糊导致误触发或无法触发）、上下文窗口污染风险、非确定性测试导致质量难以保证

### Antigravity 🔥

- **定义**：Google推出的AI编程IDE和agent-first开发平台，基于Visual Studio Code深度定制，支持Gemini 3.1 Pro、Claude Sonnet 4.6/Opus 4.6等多模型，定位为下一代AI原生编程环境。
- **起源追溯**：**2025年11月18日**随Gemini 3一同发布，**2026年5月19日**在Google I/O 2026发布2.0版本（更新桌面应用和CLI工具）。
- **提出背景**：Google将AI编程工具从"辅助Copilot"升级为"agent-first"范式，Agent可直接生成可验证的交付物（Artifacts）而非原始工具调用。
- **使用场景**：AI原生应用开发、多Agent项目管理、企业级软件开发自动化
- **交叉验证**：TechCrunch（"Google launches Antigravity 2.0" by Ivan Mehta）、The New Stack（"At Google I/O 2026, Antigravity gets a new job description"）、V2EX社区均有报道
- **争议与质疑**：与VS Code/Windsurf的关系存在争议；是否构成"高度定制fork"而非原创产品；benchmark数据缺乏
- **相关链接**：
  - [Antigravity官方文档](https://antigravity.google/)
  - [TechCrunch报道](https://techcrunch.com)
  - [The New Stack报道](https://thenewstack.io)

### Multi-Agent Orchestration 🔥

- **定义**：一种通过多个专门化AI Agent协作完成复杂任务的架构模式，每个Agent承担特定角色（如检索、生成、验证），通过结构化通信协议协调工作。
- **起源追溯**：**CAMEL论文**（arXiv:2303.17760，2023年3月31日）首次提出LLM多智能体协作框架；现代多Agent系统受分布式AI和传统multi-agent systems影响，可追溯至1980-90年代。
- **提出背景**：单Agent难以处理需要多种专业能力的复杂任务，多Agent通过专业化分工实现复杂推理，同时提高系统容错性。
- **使用场景**：金融交易（TradingAgents）、学术研究（academic-research-skills）、企业自动化（Microsoft Agent Framework）、软件开发团队模拟
- **交叉验证**：Microsoft AutoGen（58.2K stars）、Microsoft Agent Framework（2026年5月20日更新）、CrewAI、AWS Bedrock Agents、Anthropic企业部署（KPMG、PwC）均有独立验证
- **争议与质疑**：架构复杂度爆炸、Token消耗倍增、延迟累积、"大模型+好prompt足够"的单Agent派观点；学术理论框架不成熟；安全攻击面扩大
- **相关链接**：
  - [CAMEL论文](https://arxiv.org/abs/2303.17760)
  - [Microsoft AutoGen](https://github.com/microsoft/autogen)
  - [Microsoft Agent Framework](https://github.com/microsoft/agent-framework)
  - [CrewAI](https://docs.crewai.com)

### Maintainability Sensors for Coding Agents 🌱

- **定义**：通过静态分析工具（linter、复杂度分析器）监控AI编码智能体生成的代码质量，帮助Agent自我纠正和改进代码库可维护性的技术组合。
- **起源追溯**：**Martin Fowler**（2026年5月19-20日）发表文章"Maintainability sensors for coding agents"，作者为Thoughtworks Distinguished Engineer Birgitta Böckeler；后续被多位研究者验证。
- **提出背景**：AI编码智能体产生的代码常出现体量-质量逆退化（代码量增加导致结构退化），需要自动化质量监控机制来弥补。
- **使用场景**：AI辅助软件开发质量保障、企业代码规范执行、AI代码审查流程
- **交叉验证**：arXiv多篇论文（AI-Generated Smells、Quality and Security Signals、SpecBench）验证了AI编码质量问题的普遍性；GitHub上258个相关仓库
- **争议与质疑**：指标局限性（无法捕获语义可维护性）、上下文盲点、可能引发"指标游戏"（Goodhart定律）、静态分析工具对AI代码的适用性存疑
- **相关链接**：
  - [Martin Fowler文章](https://martinfowler.com/articles/sensors-for-coding-agents.html)
  - [arXiv:2605.02741 AI-Generated Smells](https://arxiv.org)
  - [arXiv:2605.21453 Quality and Security Signals](https://arxiv.org)
