## Data Collection Requirements

For each model in your target list, collect all of the following:

1. **Manufacturer** (制造商): Official native-language company name — Chinese companies in Chinese (e.g., `智谱`, `深度求索`, `月之暗面`, `阿里云`); Western companies in their official English name. Provide a verified markdown hyperlink to the manufacturer's official website.
2. **Model** (模型): Full model name with **exact, specific version number** (e.g., `GPT-4.5`, `Claude Sonnet 4.6`, `Gemini 2.5 Pro 05-06`). NEVER use a vague family name like `GPT-5` when a specific point-release or variant is publicly documented — search for the exact version before writing. Provide a verified markdown hyperlink to the model's own page (product page, API docs, or announcement post). If no model-specific page exists, omit the link.
3. **Scenario** (场景): All distinct deployment modes or access contexts for this model that carry **different technical specifications**. Each distinct scenario gets its own row in the table. Examples: `API`、`ChatGPT Web`、`Thinking (API)`、`Extended Thinking`、`Codex CLI`、`Azure OpenAI`、`Vertex AI`. For each model, **dig exhaustively** — check official docs, API references, product pages, pricing pages, changelogs, and blog posts to discover every supported deployment context. Common scenario types to investigate:
   - **API access** (direct REST/SDK calls): context limits, pricing tiers, rate limits
   - **Web interface** (consumer products): may have different context limits or feature sets
   - **Thinking/Reasoning mode**: extended thinking or chain-of-thought variants with different token budgets and pricing
   - **CLI / specialized tools**: purpose-built tools that use the model with different constraints
   - **Third-party cloud deployments** (Azure, GCP Vertex, AWS Bedrock): may have different model versions, context limits, or availability
   Do NOT be lazy — a model that appears to have one form often has multiple. If a scenario genuinely does not exist for a model, document it in the Raw Data section with evidence that you searched.
4. **Context Size** (上下文大小): Maximum context window. Human-readable format: `128K`, `1M`, `200K` — never raw numbers like `128000`. **Do NOT write `-` without first checking: official API docs, model card, arXiv paper, HuggingFace model page, and at least 2 benchmark sites. Context size is almost always documented somewhere.**
5. **Max Input** (最大输入): Maximum input tokens. Same format.
6. **Max Output** (最大输出): Maximum output tokens. Same format.
7. **Reasoning** (推理能力): Score 0–5 based on complex reasoning benchmarks (ARC, HellaSwag, MMLU, GPQA, etc.).
8. **Math** (数学能力): Score 0–5 based on math benchmarks (GSM8K, MATH, AIME, etc.).
9. **Coding** (编程能力): Score 0–5 based on coding benchmarks (HumanEval, SWE-bench, LiveCodeBench, etc.).
10. **Vision** (视觉能力): Score 0–5 for multimodal/image understanding. Use `-` if not applicable.
11. **Instruction Following** (指令遵循): Score 0–5 for adherence to complex instructions.
12. **Hallucination Control** (幻觉控制): Score 0–5 for factual accuracy.
13. **Multilingual** (多语言): Score 0–5 for non-English language support quality.
14. **Long Context Effectiveness** (长上下文有效性): Score 0–5 for actual task performance in long contexts (not just window size).
15. **JSON/Tool Call**: Score 0–5 for structured output and function calling reliability.
16. **Open Source** (开源): `✅` if open weights available; `❌` if closed. Note: open weights ≠ open source — check the license.
17. **Cost** (成本): Relative API pricing tier based on per-million-token cost.
18. **Overall** (综合评价): Composite score expressed as a **one-decimal value (0.0–5.0)** (e.g., `4.3`, `3.8`). **Display it directly in the final table** — do NOT convert to a bar symbol. Record it in the Raw Data section as well.
19. **Use Cases** (适用场景): Short comma-separated Chinese labels (e.g., `代码生成、复杂推理`; `长文档分析、多模态`).

## Model Inclusion Rules

**Include ONLY models that satisfy ALL of the following:**

1. Publicly released and accessible via API or direct public access as of today.
2. Not deprecated, superseded, or withdrawn by the manufacturer.
3. At least 3 of these key data points are publicly verifiable: context window size, at least one coding benchmark score (HumanEval / SWE-bench / LiveCodeBench / etc.), and API pricing or cost tier. If fewer than 3 are findable after exhaustive search, exclude the model and document it in the Raw Data section with the reason.

**NEVER mark data as `-` (N/A) without first:**

- Checking the official API documentation and model card
- Searching the model's arXiv paper or technical report
- Checking HuggingFace model hub, Artificial Analysis, LMSYS Arena, and Papers With Code
- Searching at least 3 community sources (Reddit, Hacker News, GitHub issues)
- Running at least 2 targeted web searches specifically for that data point

Only use `-` after all of the above yield nothing. Lazily writing `-` is not acceptable.

## Data Sources to Consult

### Tier 1 (Highest Credibility)

- Official vendor documentation and API docs
- Official model cards and release announcements
- Vendor-published official benchmark results
- arXiv academic papers for the models

### Tier 2 (High Credibility)

- LMSYS Chatbot Arena (lmarena.ai)
- Artificial Analysis (artificialanalysis.ai)
- HuggingFace Open LLM Leaderboard
- Papers With Code benchmarks
- Berkeley Function Calling Leaderboard
- SEAL leaderboard

### Tier 3 (Medium Credibility)

- Reddit (r/LocalLLaMA, r/ChatGPT, r/ClaudeAI)
- Hacker News discussions
- GitHub issues and discussions
- Technical blogs from reputable practitioners

### Tier 4 (Supplementary Only)

- TechCrunch, The Verge, Ars Technica
- InfoQ, The New Stack
- Chinese tech media (relevant for Chinese models)

**Data quality priority order (apply in sequence):**

1. **Timeliness (highest priority)**: Data from the last 3 months takes precedence above all else. Data older than 6 months must be flagged `[可能过时]`. A recent source from any tier outweighs an older Tier 1 source.
2. **Authority (second priority)**: Among sources of equal recency, prefer higher-tier sources. Official docs and benchmark leaderboards carry more weight.
3. **Credibility (third priority)**: Among sources of equal recency and tier, prefer specific numbers, reproducible methodology, and named authors over anonymous or vague claims.
4. **Cross-Verification (always)**: Every data point MUST be verified against at least 3 independent sources regardless of tier. Fewer than 3 → flag as `[待验证]`.
